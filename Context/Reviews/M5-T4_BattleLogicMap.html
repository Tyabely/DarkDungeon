1 · The whole system

Who talks to whom

The controller is the hub: it reads the click, owns the selection, paints the board and spends time on the clock. Everything else either gets told what to do (solid arrows) or listens for news (dashed arrows).

2 · BP_BattlePlayerController · EventGraph

Left click (IA_Select, Started)

Every click starts by wiping the old looks while the old selection is still stored, then changes the state, then paints the new look (Decision #145). The one exit that doesn't paint is DeselectAll: nothing is selected afterwards, so there's nothing to paint.

flowchart TD
  S(["Left click"]) --> D0["DepaintSelections · wipe old looks first"]
  D0 --> U0["GetUnitUnderCursor → Cast to BP_HeroUnit"]
  U0 -->|"cast succeeds: a hero"| Q2{"Same as SelectedHero?"}
  Q2 -->|"yes"| DA["DeselectAll · Area = None, Hero = None"]
  Q2 -->|"no"| H1["UpdateSelectedHero(hero) · clears ability, broadcasts OnSelectedHeroChanged"]
  H1 --> H2["UpdateSelectedArea(SelectedHero.CurrentArea)"]
  H2 --> P1["PaintSelections"]
  U0 -->|"cast fails: enemy or nothing"| A0["GetAreaUnderCursor"]
  A0 --> Q3{"Area hit?"}
  Q3 -->|"no"| DA
  Q3 -->|"yes"| Q4{"Same as SelectedArea?"}
  Q4 -->|"yes"| DA
  Q4 -->|"no"| Q5{"SelectedHero valid?"}
  Q5 -->|"no"| A1["UpdateSelectedArea(area)"]
  A1 --> P2["PaintSelections"]
  Q5 -->|"yes"| M1["MoveHeroToArea(area)"]
  M1 --> Q6{"Move succeeded?"}
  Q6 -->|"yes"| M2["AdvanceClock(SelectedHero.BaseMoveCost)"]
  M2 --> P3["PaintSelections"]
  Q6 -->|"no"| P4["PaintSelections"]
  • Clicking an enemy falls through to the Area path, because the cast to BP_HeroUnit fails. That's the spot where resolve will branch off ("is an ability selected?").
  • With an ability selected, an Area click still moves the hero. Decision #136 says it shouldn't; that's part of the resolve step, not built yet (T1).
  • DeselectAll calls UpdateSelectedHero(None), which also clears the ability, so all three pieces of state end up empty.
3 · Controller → BP_Unit → BP_Area

Moving a hero

MoveHeroToArea asks the unit to move, and only updates the selection when the unit says yes. The unit does the real checks: neighbour, capacity, then leaving the old Area.

flowchart TD
  C(["MoveHeroToArea(TargetArea)"]) --> U["SelectedHero.MoveToArea(TargetArea)"]
  U --> V{"TargetArea valid?"}
  V -->|"no"| F0["return false"]
  V -->|"yes"| IN{"Am I already listed in CurrentArea.UnitsInArea?"}
  IN -->|"no: first placement at spawn"| FA["TargetArea.AddUnit(self) · return its result"]
  IN -->|"yes"| NB{"TargetArea in CurrentArea.Neighbours?"}
  NB -->|"no"| F1["Print: This area is not a neighbour! · return false"]
  NB -->|"yes"| ADD{"TargetArea.AddUnit(self) · room left under Capacity?"}
  ADD -->|"no"| F2["return false"]
  ADD -->|"yes"| RM{"CurrentArea.RemoveUnit(self)?"}
  RM -->|"no"| F3["Print error · return false"]
  RM -->|"yes"| OK["CurrentArea = TargetArea · return true"]
  OK --> SEL["Controller: UpdateSelectedArea(SelectedHero.CurrentArea) · return true"]
  • AddUnit and RemoveUnit both call ArrangeUnits, which lays the units out inside the Area using the slot layouts.
  • A failed move prints twice: once in MoveToArea ("not a neighbour"), once in the controller ("Hero move not succeed!"). See R3.
4 · Controller ↔ WBP_AbilityBar ↔ WBP_AbilityButton

Ability bar

The bar fills its five slots when the selected hero changes. Each slot listens for the selected ability and paints itself green when the announced ability is its own.

flowchart TD
  subgraph HERO["When the hero changes"]
    H0(["UpdateSelectedHero"]) -.->|"OnSelectedHeroChanged"| B0["Bar: UpdateDisplay(NewUnit)"]
    B0 --> BV{"NewUnit valid and its UnitData is a PDA_Hero?"}
    BV -->|"yes"| BS["AbilitiesToDisplay = AbilitySet"]
    BV -->|"no"| BC["Clear AbilitiesToDisplay"]
    BS --> BL["For index 0 … NumberOfAbilities − 1 · Select picks slot by index"]
    BC --> BL
    BL --> BI{"IsValidIndex(AbilitiesToDisplay, index)?"}
    BI -->|"yes"| SA["slot.SetAbilityDisplayName(ability) · name, cost in s, enabled"]
    BI -->|"no"| SN["slot.SetAbilityDisplayName(None) · blank, disabled"]
  end
  subgraph CLICK["When a slot is clicked"]
    K0(["Button: On Clicked"]) --> KS["Controller: SelectAbility(AbilityToDisplay)"]
    KS --> K6["DepaintSelections"]
    K6 --> K1["Controller: UpdateSelectedAbility(AbilityToDisplay)"]
    K1 --> K2{"Same as SelectedAbility?"}
    K2 -->|"yes"| K3["SelectedAbility = None"]
    K2 -->|"no"| K4["SelectedAbility = this ability"]
    K3 --> K5["broadcast OnSelectedAbilityChanged"]
    K4 --> K5
    K5 -.-> PA["Every slot: PaintAbilityDisplay · mine and valid → green, else white"]
    K5 --> K7["PaintSelections"]
  end
  • The IsValid inside PaintAbilityDisplay is needed: an empty slot holds None, and None equals None, so without it every empty slot would turn green when the ability is cleared.
  • Since 1 Nov the button only says "clicked": SelectAbility on the controller runs Depaint → Update → Paint (I1).
5 · BP_BattlePlayerController · functions

Paint and Depaint

PaintSelections turns the current state into looks. DepaintSelections resets exactly what Paint may have touched, using PaintedAreasInRange as its memory of the range.

flowchart TD
  subgraph PAINT["PaintSelections"]
    P0(["start"]) --> PH{"SelectedHero valid?"}
    PH -->|"no: Area picked with no hero"| PA0["SelectedArea valid? → PaintArea Highlighted"]
    PH -->|"yes"| PU["hero: PaintUnitState Selected"]
    PU --> PB{"SelectedAbility valid?"}
    PB -->|"no: show moves"| PN["SelectedArea Highlighted · each Neighbour → Neighbour"]
    PB -->|"yes: show range"| PR0["SelectedArea Highlighted"]
    PR0 --> PR1["GetDistancesFromArea → Map of Area → steps"]
    PR1 --> PR2["For each entry: steps in MinRange … MaxRange? → add to AreasToPaintInRange"]
    PR2 --> PR3["For each in AreasToPaintInRange: PaintArea InRange · add to PaintedAreasInRange"]
  end
  subgraph DEPAINT["DepaintSelections"]
    D0(["start"]) --> DQ{"SelectedArea valid?"}
    DQ -->|"no: skip the Area part"| D2
    DQ -->|"yes"| D1["SelectedArea → Normal · its Neighbours → Normal"]
    D1 --> D2["each in PaintedAreasInRange → Normal · Clear the list"]
    D2 --> D3["SelectedHero valid? → PaintUnitState Normal"]
  end
  • GetDistancesFromArea (on BP_Area) spreads out ring by ring: ring 0 is the start Area, ring N+1 is every neighbour of ring N not seen yet. It stops when a pass adds nothing new.
  • Two loops and a list where one loop would do: R1. With no SelectedArea, Depaint still clears the range and the hero (I2, corrected).
6 · BP_BattleGameState → BP_BattleGameMode → BP_EnemyUnit

Clock and enemy attacks

Spending time is the only thing that moves the battle forward. When the clock moves, the Game Mode lets every enemy whose attack is due strike, one at a time, earliest first.

flowchart TD
  A0(["AdvanceClock(BattleClockIncrease)"]) --> A1["ClockTimeTenths += BattleClockIncrease"]
  A1 -.->|"OnClockAdvanced(NewTimeTenths)"| W["WBP_BattleClock: SetClockInfo · shows 12.5s"]
  A1 -.->|"OnClockAdvanced(NewTimeTenths)"| R0["Game Mode: ResolveNextAttack(NewTimeTenths)"]
  R0 --> R1["ResolveTimeTenths = NewTimeTenths · FindEarliestAttacker"]
  R1 --> R2{"Any enemy left?"}
  R2 -->|"no"| RX["stop"]
  R2 -->|"yes"| R3{"Its attack due ≤ ResolveTimeTenths?"}
  R3 -->|"no"| R4["every enemy in EnemyQueue: UpdateIntentLabel"]
  R3 -->|"yes"| R5["enemy.ResolveAttack · print, InternalClock += attack time, SelectNextAttack"]
  R5 --> R6["Delay 0.1 s"]
  R6 --> R7["every enemy: UpdateIntentLabel"]
  R7 --> R0b["ResolveNextAttack again · same time"]
  R0b --> R1
  • Each enemy keeps its own InternalClockTenths. "Due" = its internal clock + the current attack's time, from GetNextAttackDue.
  • ResolveAttack only prints and logs for now; it doesn't damage a hero yet (T2).

9 · The rule check

Selection state: one way in

The Update… rule says every piece of selection state has exactly one function that writes it. As of today it holds for all three.

I1The button runs the controller's painting, in the wrong orderdone 1 Nov

1 Nov: controller SelectAbility(NewAbility) = Depaint → UpdateSelectedAbility → Paint; On Clicked calls only that (Decision #149).

On Clicked does Update → Depaint → Paint. The rule (#145) is Depaint → Update → Paint, and the widget shouldn't need to know painting exists. Give the controller one entry point, e.g. SelectAbility(Ability) = Depaint → UpdateSelectedAbility → Paint, and let the button call only that.
